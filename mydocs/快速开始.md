# DeepTutor 快速开始

> 目标：让一个新人在最短时间内**跑起来、配置模型、发出第一条消息、跑通第一组测试，并知道接下来读哪些文件**。
>
> 说明：本文按当前源码与 `README.md`、`docs-for-dev/AGENT_SETUP.md`、`docs-for-dev/DEVELOPMENT.md`、`docs-for-dev/TESTING.md` 整理。当前 shell 没有可用的 Python 解释器，所以本文的命令**未在本地实跑**，属于静态整理。

---

## 0. 选择你的路径

| 你的目标 | 推荐路径 | 需要什么 |
|---|---|---|
| 先体验完整 Web 应用 | **Docker** | Docker |
| 只用 CLI / SDK | **PyPI 核心包** | Python 3.11–3.14 |
| 参与开发 / 改代码 | **源码安装** | Python 3.11–3.14（推荐用 uv）、Node.js 22 LTS、Git |
| 桌面 App | 下载 Release 安装包 | macOS/Windows |

## 1. 最快路径

### 1.1 Docker（体验完整 Web 应用）

```bash
docker run --rm --name deeptutor \
  -p 127.0.0.1:3782:3782 \
  -v deeptutor-data:/app/data \
  ghcr.io/hkuds/deeptutor:latest
```

打开：

```text
http://127.0.0.1:3782
```

说明：

- 命名卷 `deeptutor-data` 保存设置和本地数据；
- 只需要暴露 `3782` 一个端口；
- 首次进入后在 **Settings → Providers / Language models** 配置模型。

### 1.2 PyPI（完整 Web App / CLI）

```bash
mkdir -p my-deeptutor && cd my-deeptutor
python -m pip install -U "deeptutor[full]"
deeptutor init
deeptutor start
```

打开终端打印的 URL，默认：

```text
http://127.0.0.1:3782
```

CLI-only：

```bash
python -m pip install -U deeptutor
deeptutor init --cli
deeptutor chat
```

> 核心包 `deeptutor` 只有 chat / ask_questions / CLI / SDK；其他能力需要对应模块。

### 1.3 源码（推荐给开发者）

```bash
git clone --branch dev https://github.com/HKUDS/DeepTutor.git
cd DeepTutor

python3 -m venv .venv
source .venv/bin/activate          # Windows PowerShell: .venv\Scripts\Activate.ps1

python -m pip install --upgrade pip
python -m pip install -r requirements/full.txt
python -m pip install -e . --no-deps

(cd web && npm ci --legacy-peer-deps)

deeptutor init
deeptutor start --dev
```

#### 用 uv（推荐，当前环境已安装）

当前 shell 中 `uv` 可用（`uv --version` 为 0.12.3），并且 uv 已管理 Python 3.12.13 / 3.14.4。

```bash
git clone --branch dev https://github.com/HKUDS/DeepTutor.git
cd DeepTutor

# 1) 创建虚拟环境（用 uv 管理的 Python 3.12）
uv venv --python 3.12

# 2) 激活
source .venv/Scripts/activate        # Git Bash on Windows
# PowerShell: .venv\Scripts\Activate.ps1
# macOS/Linux: source .venv/bin/activate

# 3) 安装依赖
uv pip install -r requirements/full.txt
uv pip install -r requirements/dev.txt
uv pip install -e . --no-deps

# 4) 前端依赖（仍然用 npm）
(cd web && npm ci --legacy-peer-deps)

# 5) 初始化与启动
deeptutor init --non-interactive
deeptutor start --dev
```

如果不想激活 venv，可以用：

```bash
uv run --no-sync deeptutor init --non-interactive
uv run --no-sync deeptutor start --dev
uv run --no-sync python -m pytest -q tests/app tests/runtime/coordination
```

说明：

- `--no-sync` 表示“只运行，不重新同步/安装依赖”，避免 uv 根据 `pyproject.toml` 重新解析环境；
- `uv` 只负责 Python 环境；前端仍然需要 `npm ci --legacy-peer-deps`；
- `requirements/full.txt` + `requirements/dev.txt` 组合覆盖完整应用与开发工具；
- 桌面端构建也会用到 `uv`（见 `apps/desktop/README.md`）。

Windows 提示：

- 用受支持的 `py -3.X` 或 `uv venv --python 3.12` 创建 venv；
- 命令在 Git Bash / PowerShell 中都可执行，注意路径分隔符；
- 如果没有 `python`，先安装 Python 3.11–3.14 或让 uv 管理 Python。

## 2. 源码安装逐步说明

### 2.1 前置条件

| 依赖 | 版本 |
|---|---|
| Python | 3.11–3.14 |
| Node.js | 22 LTS |
| npm | 随 Node |
| Git | 任意较新版本 |
| uv（推荐） | 任意较新版本；本环境为 0.12.3 |

可选系统依赖：

- **ffmpeg / LaTeX**：`math_animator` 的 Manim 渲染；
- **Docker**：代码/视频沙箱；
- **Manim/Python 依赖**：`python scripts/install_extras.py math-animator`；
- **Partner 通道 SDK**：`python scripts/install_extras.py partners`；
- **Matrix**：`python scripts/install_extras.py matrix` 或 `matrix-e2e`；
- **开发工具**：`python scripts/install_extras.py dev`。

### 2.2 安装 Python 依赖

**方式 A：uv（推荐）**

```bash
uv venv --python 3.12
source .venv/Scripts/activate        # Windows Git Bash
# PowerShell: .venv\Scripts\Activate.ps1
# macOS/Linux: source .venv/bin/activate

uv pip install -r requirements/full.txt
uv pip install -r requirements/dev.txt
uv pip install -e . --no-deps
```

**方式 B：pip**

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements/full.txt
python -m pip install -e . --no-deps
python scripts/install_extras.py dev
```

不激活 venv 时，用：

```bash
uv run --no-sync python -m pytest ...
uv run --no-sync deeptutor ...
```

为什么是 `--no-deps`？

- `requirements/full.txt` 已经安装外部依赖；
- `-e . --no-deps` 只安装本项目，避免 pip 重复解析/覆盖；
- 源码检出包含所有模块，因此需要 full 依赖。

### 2.3 安装前端依赖

```bash
cd web
npm ci --legacy-peer-deps
cd ..
```

`--legacy-peer-deps` 是项目约定的安装方式，避免 npm 对 peer dependency 的严格解析。

## 3. 运行时目录与配置

### 3.1 什么是 `DEEPTUTOR_HOME`

`DEEPTUTOR_HOME` 是“拥有 `data/` 的目录”，不是 `data/` 本身。

推荐开发时用一个独立 home：

```bash
export DEEPTUTOR_HOME="$HOME/.local/share/deeptutor-dev"
deeptutor init --non-interactive
```

Windows PowerShell：

```powershell
$env:DEEPTUTOR_HOME = "$env:USERPROFILE\deeptutor-dev"
deeptutor init --non-interactive
```

注意：

- 项目根目录的 `.env` **不会自动加载**；
- 设置保存在 `$DEEPTUTOR_HOME/data/user/settings/`；
- 模块启用状态在 `$DEEPTUTOR_HOME/data/system/modules.json`；
- 日志在 `data/user/logs/deeptutor.jsonl`；
- launcher 日志在 `data/user/runtime/launcher.log`。

### 3.2 初始化

```bash
deeptutor init --non-interactive
deeptutor config show
deeptutor module list
```

`init --non-interactive`：

- 创建缺失的默认文件；
- 不选择模型、不联系 provider；
- 保留已有设置。

`--cli` 也可用；两种模式都不会启动向导。

### 3.3 查看支持的 provider

```bash
deeptutor config providers
```

它会输出支持的 LLM / embedding / search provider、默认 endpoint、API format（JSON）。用其中的 provider ID。

### 3.4 用 JSON 应用配置

创建 `setup.json`（不要放明文 key，只放环境变量名）：

```json
{
  "llm": {
    "provider": "openai",
    "model": "YOUR_MODEL_ID",
    "api_key_env": "DEEPTUTOR_SETUP_LLM_KEY"
  },
  "system": {
    "backend_port": 8001,
    "frontend_port": 3782
  }
}
```

确保变量存在于当前 CLI 进程环境：

```bash
export DEEPTUTOR_SETUP_LLM_KEY="..."   # 不要写进仓库
deeptutor config apply setup.json --check
deeptutor config apply setup.json
deeptutor config show
```

`--check` 会校验 provider、凭据变量、endpoint、端口冲突，不写设置、不联系 provider。非法输入退出码为 2。

### 3.5 Embedding / RAG（可选）

如果要用知识库/RAG，需要配置 embedding：

```json
{
  "embedding": {
    "provider": "openai",
    "model": "text-embedding-3-small",
    "api_key_env": "DEEPTUTOR_SETUP_EMBEDDING_KEY",
    "dimension": 1536
  },
  "search": { "provider": "duckduckgo" }
}
```

注意：

- embedding 的 `base_url` 是完整 endpoint（如 `https://api.openai.com/v1/embeddings`）；
- 修改已有 KB 的 embedding 模型/维度需要重建索引；
- DuckDuckGo 不需要 key，但依赖网络。

### 3.6 OAuth provider

```bash
deeptutor provider login openai-codex
# 其他：github-copilot、codebuddy
```

OAuth 登录不会自动选择模型；登录后仍需在 Settings 或 `config apply` 选择模型。

## 4. 启动与验证

### 4.1 一键启动（后端 + 前端）

```bash
deeptutor start --dev
```

生产构建：

```bash
deeptutor start
```

后台启动：

```bash
deeptutor start --detach --no-browser
deeptutor stop
```

默认地址：

| 服务 | 地址 |
|---|---|
| 后端 | `http://127.0.0.1:8001` |
| 前端 | `http://127.0.0.1:3782` |

以 launcher 实际输出为准；端口冲突时用 `config apply` 选择空闲端口，不要停掉无关进程。

### 4.2 分开启动后端 / 前端

终端 1：

```bash
deeptutor serve --host 127.0.0.1 --port 8001 --reload
```

终端 2：

```bash
cd web
DEEPTUTOR_API_BASE_URL=http://127.0.0.1:8001 npm run dev
```

确认浏览器请求能通过前端代理到达后端；只看到前端监听不代表模型/模块/ turn 就绪。

### 4.3 验证 readiness

```bash
python -m pip check
deeptutor module list
deeptutor doctor --format json
deeptutor doctor --online --format json
```

- `pip check`：依赖一致性；
- `module list`：installed / enabled / ready；
- `doctor`：本地 readiness；
- `doctor --online`：真实模型请求，可能产生 provider 用量；
- `doctor runtime`：turn 协调、session 存储、迁移预检。

### 4.4 第一条 turn

```bash
deeptutor run chat "用一句话解释傅里叶变换" --format json
```

检查：

- 有成功 response；
- turn 走到完成（不是只看到第一个流式事件）；
- JSON 事件里能看到 `done` / `usage_summary`。

> **重要**：同一个 runtime home 只能有一个 turn-owning 进程。  
> 如果 `deeptutor start --detach` 还在运行，不要再对同一个 home 执行 `deeptutor run chat`；先 `deeptutor stop`，否则可能触发 `worker_lost` / `Turn event conflict`。

## 6. 第一次读代码：一条 chat turn 的路径

不要从 `services/` 开始；先沿着一条消息走。

```text
deeptutor_cli/main.py:77            // deeptutor run
  → deeptutor_cli/common.py:129     // run_turn_and_render
  → deeptutor/app/facade.py:129     // DeepTutorApp.start_turn
  → deeptutor/app/service.py:113    // TurnApplicationService.start_turn
  → services/session/turns/request_preparer.py
  → services/session/turns/executor.py
  → runtime/turn_engine.py:17
  → runtime/orchestrator.py:64
  → agents/chat/capability.py:12
  → agents/loop/pipeline.py:403
  → agents/loop/agent_loop.py:208
  → runtime/agentic/tool_dispatch.py
  → services/session/turns/lifecycle.py:681
  → services/session/sqlite_store.py
```

建议的阅读顺序：

1. `deeptutor/app/service.py` — admission / 幂等 / 订阅回放；
2. `deeptutor/services/session/turns/request_preparer.py` — 租约 / `begin_turn`；
3. `deeptutor/services/session/turns/executor.py` — `UnifiedContext` / `turn_engine.execute`；
4. `deeptutor/runtime/turn_engine.py` + `runtime/orchestrator.py` — 路由；
5. `deeptutor/agents/chat/capability.py` + `agents/loop/pipeline.py` — 能力/循环；
6. `deeptutor/core/stream.py` + `runtime/stream_bus.py` — 事件；
7. `deeptutor/services/session/turns/lifecycle.py` — 持久化/flush；
8. `deeptutor/services/session/sqlite_store.py` — 存储 schema。

更详细的场景链路见 [`代码链路场景解析.md`](./代码链路场景解析.md)；整体架构见 [`整体架构代码阅读报告.md`](./整体架构代码阅读报告.md)。

## 8. 常见问题

### 8.1 启动后页面能开，但模型不回复

检查：

```bash
deeptutor config show
deeptutor doctor --format json
deeptutor doctor --online --format json
```

常见原因：

- 没有选择模型；
- `api_key_env` 指向的变量不存在；
- provider endpoint / API format 不匹配；
- 本地 Ollama 没启动或模型未拉取；
- OAuth 登录了但未选择模型。

### 8.2 `deeptutor run chat` 报 `worker_lost` / `Turn event conflict`

原因：同一个 runtime home 同时有一个 `deeptutor start --detach` 在跑。

处理：

```bash
deeptutor stop
deeptutor run chat "..."
```

或者先跑 CLI 验证，再启动 Web。

### 8.3 端口被占用

```bash
deeptutor config apply setup.json --check
deeptutor config apply setup.json
```

选择空闲端口后重启。不要停掉无关进程。

### 8.4 模块显示 installed 但 not ready

```bash
deeptutor module list
```

看 issues：

- 依赖包缺失/版本不匹配；
- 必需模块未启用；
- 系统可执行文件缺失（ffmpeg、latex、docker 等）。

源码：`deeptutor module enable <name>`；wheel：`deeptutor module install <name>`。

### 8.5 改了模块/依赖后启动失败

- 先停 DeepTutor；
- 用 uv 时：`uv pip install -r requirements/full.txt`、`uv pip install -r requirements/dev.txt`，再用 `uv run --no-sync deeptutor ...`；
- 源码用 `python scripts/install_extras.py <extra>`；
- 不要用 feature wheel 覆盖 editable 源码；
- 检查 `python -m pip check` 和 `deeptutor module list`。

### 8.6 前端改了契约但页面报错

- `cd web && npm run contracts:generate`；
- 检查 `npm run contracts:check`；
- 后端 schema 变更后，重新生成并提交 `web/contracts/` 的 diff。

### 8.7 测试被跳过

部分测试需要显式环境：

- `DEEPTUTOR_TEST_REDIS_URL`：Redis；
- `DEEPTUTOR_TEST_VIDEO_SANDBOX=1`：真实视频渲染；
- 其他 integration/opt-in 变量。

看 skip 条件，不要声称“全绿”而忽略 skipped。
